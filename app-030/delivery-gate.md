# 交付关卡说明（delivery gate）

本应用承诺「量体数据不出本机」。学生名单、下单表一旦被打进包带出门，承诺即告破产，
而这一步原来只能靠人盯。本关卡把这一步固化成一条命令：跑完给出结论，
**打包侧、页面上的交付自检（`/delivery`）、导出说明（导出页卡片）三处读同一份机读结论
`delivery-report.json`，任何一处不得自行另写判断。**

```bash
npm run gate          # 默认硬拦：任一检查不过，命令非零退出，不得继续 docker build
npm run gate:report   # 只出报告：结论照写，但不拦打包（见「取舍二」的适用条件）
npm run pack          # 关卡通过后才执行 docker compose build
```

机读结论写入 `public/delivery-report.json`（随 docker 构建进入镜像）与
`dist/delivery-report.json`（本地包内），每项检查都带：过没过（pass/fail/skip）、
证据（evidence）、跳过原因（skipReason）。

## 取舍一：包里允不允许留一份示例数据

**决定：一律剥干净，包里不放任何示例量体数据。** 演示靠现场新建项目手工录入几条，
或导入使用方自己的文件。唯一随包的数据文件是 `src/data/size-rules.json`
（号型规则表，是公开规则不是个人信息）。

两条路的代价：

- 留一份示例：演示开箱即用，但「示例」与「真实」的边界会随时间模糊——
  今天放的是编造的 30 人，明天有人图省事把真实班级名单改名「示例」放进去，
  关卡和人都未必分得出来。边界一旦靠自觉，就等于没有边界。
- 一律剥干净：演示前要花两分钟录数据，但规则只有一句「包里没有任何名单」，
  机器可查、人不用判断。

**以下情况必须选剥干净（无豁免）：**

1. 文件含真实姓名、班级/车间、身体尺寸中的任何一项；
2. 文件来源于任何一次真实导出（哪怕已「脱敏」——脱敏是否彻底无法由关卡证明）；
3. 无法拿出证据证明数据为合成数据时，一律按真实数据处理。

## 取舍二：自检不过时硬拦还是只出报告

**决定：默认硬拦。** 任一检查不过，`npm run gate` 以非零退出，`npm run pack`
不会执行到 `docker compose build`。

两条路的代价：

- 硬拦：能确实挡住带名单出门，但临时要打个演示包、或本机缺工具导致误伤时，
  打包走不通。
- 只出报告：灵活，但「报告有人看」是个假设，深更半夜赶工时不成立。

**以下情况必须硬拦（即使临时打包也不许放行）：**

1. 包内或构建上下文中命中名单类文件（表格、CSV、名单命名）——这直接违反
  「数据不出本机」承诺，没有「临时」一说；
2. 依赖声明与锁定不一致——此时装出来的东西没人能复现，包的内容不可知；
3. 任何涉及隐私承诺的检查项不过时。

降级为只出报告（`--report-only`）只允许用于：本机缺工具导致检查被跳过、
或确需临时出演示包的场景，且报告必须随包留档、由人确认不过项与隐私无关。

## 检查项（按执行顺序）

| # | 检查项 | 不过的含义 |
|---|--------|-----------|
| 01 | 依赖声明与锁定对照 | package.json 里写了、package-lock.json 里没有的，当场点名 |
| 02 | 声明 / 锁定 / 实装同一套 | 锁定版本与 node_modules 实装版本逐包比对，多装少装都算不过 |
| 03 | 构建体积与文件数 | 报出 dist/ 多大、多少个文件 |
| 04 | 包内卫生 | 表格、逗号分隔文本、源码目录、依赖目录、环境文件、上次构建残留（mtime 早于本次构建）一律不得出现 |
| 05 | 内容指纹与缓存期限 | 首页引到的带版本号文件名必须含内容指纹；指纹资源允许缓存一年（immutable），首页不许缓存 |
| 06 | 容器端口与探活 | 对外写的端口（compose 映射容器侧）与里面实际听的（nginx listen / EXPOSE）必须同一个；/healthz 必须回 200 "ok" |
| 07 | 带编号地址刷新 | /measure/:id 等带编号地址逐个打开刷新，必须都回到同一份 index.html |
| 08 | 构建上下文排除 | .dockerignore 必须排除 node_modules、dist、.git、.env、日志与名单类数据；上下文 < 5MB 且不含名单类文件 |
| 09 | 重复打包一致性 | 同一提交连续构建两次，文件清单与逐文件体积标记必须完全一致 |

机器上没有相应工具时（如本机无 docker），对应运行时检查跳过并在结论里写明原因，
由静态核对替代；跳过不算过，部署机上需补跑。

## 构建上下文必须排除的目录（第 08 项的依据）

`node_modules`（镜像内重新 `npm ci`）、`dist`（镜像内重新构建）、`.git`、
`.env`/`.env.*`、`*.log`、`coverage`、编辑器目录、`Dockerfile`/`docker-compose.yml`/
文档，以及 **`data/`、`samples/`、`exports/`、一切 `*.csv`/`*.xlsx`/`*.xls`（量体名单与下单表）**。
`package-lock.json` 与 `src/data/size-rules.json` 必须保留在上下文内；
`nginx.conf` 不能排除（运行阶段要 COPY 它）。

## 已知环境差异

- `docker-compose.yml` 对外端口为 `8260:80`，规格文档示例写的是 `8110:80`；
  关卡只核对「映射的容器侧端口 == nginx listen == EXPOSE」，对外端口以 compose 为准。
- 本机无 docker 时第 06 项运行时探活跳过；第 07 项用 `vite preview` 对构建产物实测，
  nginx 行为以静态核对为准。
